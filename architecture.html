System Design

Architecture of Courier Symphony

Courier Symphony coordinates autonomous agents, workers, and tools into a single auditable execution graph. Every task runs under strict admission, writes to an append-only ledger, and resumes safely from checkpoints after failures.

Core Architectural Pillars

1. Admission Control & Host Isolation
Heavy tasks require explicit admission tokens. A host never runs more than one heavy builder simultaneously, preventing out-of-memory crashes and thrashing.
2. Append-Only Execution Ledger
State transitions are recorded in an immutable journal. Claims are leased with timeouts. If a worker process halts or crashes, the ledger state remains intact and uncorrupted.
3. Pluggable Provider Abstraction
Work units can execute across heterogeneous providers (Cursor, Codex, Muse, Antigravity, or local worker scripts). Providers must qualify via automated probes before receiving production tasks.
4. Verification & Result Receipts
A task is not marked complete because a process exited with zero; completion requires cryptographically hashed result artifacts read back and validated by an independent verifier.
5. Zero Duplicate Side Effects
Retry storms and repeated API calls are strictly avoided through idempotency keys derived from claim event IDs and specification fingerprints.
6. Cross-Platform Runtime
Designed to coordinate local development nodes (macOS, Windows, Linux) alongside transient burst cloud compute on AWS, keeping local hosts responsive.

Evidence & Reproducibility

Courier Symphony adheres to an evidence-first rule: no technical capability is claimed on this site without an automated test suite, an immutable Git SHA, and a reproducible verification record.
