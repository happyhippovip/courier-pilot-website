System Design

Architecture of Courier Symphony

Courier Symphony coordinates autonomous agents, workers, and tools into a single auditable execution graph. Every task runs under strict admission, writes to an append-only ledger, and resumes safely from checkpoints after failures.

Prototype sketch

Architectural pillars (goals)

These describe the direction of the prototype. Only the evidenced controller/worker demo (PR #361) is claimed as demonstrated so far.

1. Admission control & host isolation
Heavy work should require admission so a host does not thrash. Full multi-builder admission packaging is still in progress.
2. Append-only execution ledger
State transitions are recorded in a journal so a crash does not erase progress. Leases are time-bounded in the prototype design.
3. Pluggable provider abstraction
Work units can target different providers over time. Real provider adapters beyond the synthetic demo are in progress, not finished product claims.
4. Verification & result receipts
Exit code alone is not enough: success should require evidence that an independent verifier can check. Demonstrated with the synthetic adapter path in PR #361.
5. Avoid duplicate side effects
Retries should reuse stable effect keys. The hard-kill/restart demo showed 0 duplicate tasks with a synthetic adapter.
6. Cross-platform runtime
Target picture: coordinate local nodes and optional cloud workers. Clean-machine Windows shipping is not claimed here.

Evidence & Reproducibility

Evidence-first rule: public pages should not present a capability as finished without a concrete demo, test, or Git SHA. The primary evidenced demo today is PR #361.
