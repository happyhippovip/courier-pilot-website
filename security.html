Security Model

Security by Construction

Autonomous software should never operate with unchecked authority. Courier Symphony is engineered from the ground up with fail-closed safety, strict isolation, and cryptographic auditing.

Five Non-Negotiable Tenets

1. Fail-Closed on Unknown Outcomes
When an external API times out, a provider disconnects, or evidence is missing, the system never assumes success. It enters a BLOCKED or UNKNOWN state and awaits verification rather than blind retries.
2. Zero Autonomous Spending
Courier Symphony has no authority to make unauthorized financial commitments or automatically charge credit cards. Hard spend limits, budget alarms, and human approval gates protect every cloud resource.
3. Zero Raw PII in Ledgers
Customer contact details and sensitive identifiers are never committed in plaintext. Orders use salted SHA-256 cryptographic hashes for lookups, ensuring git histories and state dumps remain clean.
4. Least Privilege & Ephemeral Scopes
Workers never receive long-lived root credentials. Tasks execute in isolated git worktrees or throwaway containers with short-lived tokens scoped only to the exact files being modified.
5. Verifiable Receipts & Clean Deletion
Every completed delivery records an immutable SHA-256 digest of the output file. When auditing customer repositories, copies are purged within 48 hours after report delivery.

Repository Data Protection

For services such as the Repo Reality Check:

  • Read-Only Access: We only inspect public repositories or ZIP archives. We never request write permissions, deploy keys, or private user passwords.
  • No Code Execution: Static analysis is performed safely without executing untrusted test scripts or installing arbitrary third-party package dependencies.
  • Strict Retention Limit: Repository working trees are completely deleted after the verification report is generated and delivered.
