Technical Specifications

Developer Primitives & Core Contracts

Courier Symphony provides minimal, durable building blocks that replace complex distributed workflow frameworks with deterministic OS files and verifiable receipts.

1. The Append-Only Execution Ledger

All state transitions are recorded as immutable, monotonically sequenced JSONL events.

2. Atomic Work Queue State Machine

The work queue guarantees exactly-once processing with lease-based fencing and automatic recovery.

SEEDED

Work item registered with scope boundaries, dependencies, and required runtime capabilities.

CLAIMED

Worker holds an exclusive, time-bounded lease. Parallel claims on overlapping scopes are rejected immediately.

COMPLETED

Execution succeeded and produced a valid verification receipt. The item is retired and never re-executed.

EXPIRED / RELEASED

If a worker crashes or fails heartbeat checks, the lease expires cleanly and returns to the pool with failure evidence.

3. Fail-Closed CLI & Audit Engine

Courier Symphony includes standalone verification tools that run locally or in CI without external dependencies.

Work Queue Audit Engine (work_queue_audit.py)

Audits ledger files for cryptographic and state machine consistency:

  • Chronological Monotonicity: Rejects timestamps moving backwards in time (TIME_TRAVEL).
  • Scope Collision Detection: Verifies no two concurrent workers claimed intersecting codebase files (CONCURRENT_SCOPE_CONFLICT).
  • State Invariant Auditing: Catches illegal double claims, unheld releases, or expired lease extensions.
python -m courier_core.work_queue_audit --ledger /path/to/ledger.jsonl --fail-closed
# Output: {"ok": true, "events_audited": 142, "items": 9, "violations": []}

Automated CI/CD Gate (GitHub Actions / GitLab CI)

Integrate Courier state verification directly into pull request checks. Fails the build immediately if illegal state transitions or concurrent file mutations are detected:

name: Courier Audit Gate
on: [push, pull_request]

jobs:
  verify-ledger:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Code & Ledger
        uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: '3.12'

      - name: Audit Ledger Invariants
        run: |
          python -m courier_core.work_queue_audit \
            --ledger logs/ledger.jsonl \
            --fail-closed

4. The Verifiable Receipt Contract

Courier workers generate machine-checkable verification receipts upon task completion. Every receipt binds execution output to a cryptographic SHA-256 fingerprint.

Verification Receipt Schema (receipt.schema.json)

📥 Download Schema (.json) 
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "CourierReceipt",
  "type": "object",
  "required": [
    "receipt_id",
    "item_id",
    "timestamp",
    "status",
    "fingerprint",
    "tests_passed"
  ],
  "properties": {
    "receipt_id": {
      "type": "string",
      "pattern": "^rcpt-[0-9a-fA-F-]{8,}$"
    },
    "item_id": {
      "type": "string"
    },
    "worker_id": {
      "type": "string"
    },
    "timestamp": {
      "type": "string",
      "format": "date-time"
    },
    "status": {
      "type": "string",
      "enum": ["SUCCESS", "FAILED", "BLOCKED"]
    },
    "fingerprint": {
      "type": "string",
      "pattern": "^[0-9a-f]{64}$",
      "description": "SHA-256 digest of modified trees and output artifacts"
    },
    "tests_passed": {
      "type": "integer",
      "minimum": 0
    },
    "execution_duration_ms": {
      "type": "number"
    }
  }
}
